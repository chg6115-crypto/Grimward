## 0. 적용 방법 (순서대로)

1. **이전 코드 보관** (Unity를 닫고, 프로젝트 폴더에서)
   ```
   git add -A
   git commit -m "Archive code before restart"
   git tag archive/pre-restart
   ```
2. **이전 코드 삭제** (`.meta`도 같이)
   - `Assets/_Project/Scripts/`
   - `Assets/_Project/Editor/`
   - `Assets/_Project/Data/`
   - `Assets/_Project/Scenes/` (Main, HexTileTest)
   - `Assets/Tests/`
   - 남겨 둘 것: `Assets/_Project/Art/`, `Assets/_Project/Prefabs/` (M2 지도에서 다시 씀. HexTile 프리팹은 스크립트가 빠져 Missing Script가 뜨는데 M2에서 다시 연결)
3. **새 코드 복사**: 이 폴더(`Claude outputs\M0_M1_v2`)의 `Assets/` 안 내용을 프로젝트 `Assets/`에 그대로 덮어 넣기 (이전 `M0_M1` 폴더는 쓰지 않음, 지워도 됨)
4. **Unity 열기** → 상단 메뉴 **Grimward → M0 씬 만들기** → 한글 폰트 에셋(NotoSansKR SDF) 생성, `Title`·`Town`·`Expedition`·`BattleTest` 씬과 UI를 Hierarchy에 만들어 저장 + Build Settings 등록, BattleTest 씬이 열림
5. **Play** → 전투 테스트
6. **Window → General → Test Runner → EditMode → Run All** (38개)
7. 확인되면 커밋 + 태그 `v0.1-m1`

## 2. 실행·확인 방법

- 화면 배치 (다키스트 던전 방식)
  - 위: 라운드 번호(가운데), 현재 차례(왼쪽), 도주(오른쪽)
  - 가운데: 진형 — 왼쪽 플레이어 4 3 2 1 | 1 2 3 4 몬스터. 노란 테두리 = 지금 차례, 빨강 = 노릴 수 있는 적, 초록 = 고를 수 있는 아군, 흰색 = 정보 보는 중
  - 좌하단: 모험가 패널 (기술 4 · 이동 · 넘기기 · 능력치 · 효과)
  - 우하단: 가방 6×2 + 전투 기록. 몬스터 칸을 누르면 몬스터 정보로 바뀌고 X로 닫음
- 조작: 기술 → 빨강/초록 칸. 자신·아군 전체·소환 기술은 바로 사용. 이동 → 옆 아군. 가방 아이템 → 아군(턴 소모 없음, 턴당 1개). 같은 버튼을 다시 누르면 선택 취소
- 선택 중이 아닐 때 아군 칸 → 그 모험가 정보, 몬스터 칸 → 몬스터 정보
- BattleTestBootstrap Inspector: 파티(2인/4인 A/4인 B), 편성, 밤, 시드, 회복약·약초·열쇠·횃불 수
- 배치·색은 씬에서 직접 고치면 된다. 「다시 만들기」 메뉴는 손으로 고친 것을 지우므로 주의

## 3. 테스트 결과

- 이 작업 환경에서 .NET 8 + NUnit으로 Domain과 테스트를 컴파일해 **38개 전부 통과** 확인
- 추가로(하네스 전용, 프로젝트에 넣지 않음) 실제 `gamedata.json` 검증, 5개 직업 Lv1 능력치가 엑셀(22_기술 제목줄)과 일치하는지 확인, 자동 전투 2,100회 무오류
- Presentation·Editor 코드는 Unity 없이는 컴파일 확인을 못 했다. 콘솔 오류가 나면 그대로 붙여 주면 바로 고친다

## 5. 임의로 정한 것과 이유

- **데이터 형식을 ScriptableObject 대신 JSON 한 파일로**: 엑셀 → 데이터 반영이 한 번에 되고, Domain 정의 클래스를 그대로 써서 변환 코드가 없음. 개발규칙 4장을 이에 맞게 고침
- **자기 차례에 자신에게 건 효과**(전투의 함성, 방패 막기)는 그 차례 끝에 줄지 않게 함. 글자 그대로 하면 3라운드 버프가 사실상 2라운드가 되기 때문
- **위치 이동이 진형 끝을 넘으면** 마지막 칸에서 멈춤 (2인 파티에서 2칸 밀기 → 2번 칸)
- **소환된 몬스터**는 다음 라운드부터 행동
- **피해 0 허용**: 공식대로 버림 결과가 0이면 0 (저주 침 등). 최소 1이 필요하면 상수로 추가
- 기술 레벨 2~5는 명중·피해·치명 보정만 반영. 효과 수치의 레벨별 변화(전투의 함성 +20% 등)는 v0.1이 Lv1 시작이라 아직 미반영

## 6. 기획과 다르거나 모호했던 곳

- **밸런스**: 단순 자동 조작으로 300전씩 돌린 결과 — 2인 vs 튜토리얼 100% 승, 4인 vs 일반 100%, 4인 vs 보스방 100%(평균 7.1라운드), **2인 vs 악마 97% 승**. 튜토리얼 악마(사실상 지는 전투)와 습격 악마 모두 너무 약하고, 전반적으로 플레이어가 강함 → M4 수치 조정 때 몬스터 HP·공격력부터 검토 필요
- 「응급처치」 지능 비례: Lv1 궁수 +3. 마법사 지능 6이면 +6이 되지만 v0.1 마법사는 응급처치가 없음
- 「매직 애로우」 크리티컬 보정 0, 방어도 무시로 구현

## 7. 다음 마일스톤(M2 탐험)을 위한 확장 지점

- `BattleState.Create(db, rng, 파티, 편성 ID, 밤 여부, 보급품)` — 탐험 노드에서 그대로 호출
- `BattleState.KilledMonsterIds`(의뢰 집계), `Outcome`(승리·전멸·도주 → 후퇴), 종료 시 모험가 HP·사망 반영
- `BattleInventory` → M2의 가방(12칸)으로 교체
- `GameTime.IsNight`, `HexCoord` 준비됨. 지도·노드 데이터와 `IMapProvider`는 M2에서 새로 작성
